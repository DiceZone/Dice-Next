## 更新日志

### 2026-08-06 · build 791

- **多账号群管理（同群多个骰娘）**：同一客户端登录多个 OneBot 账号时，后登录账号不再覆盖先前账号的群列表与开关状态。群开关、锁定、AI、群名片、欢迎语、插件状态与当前日志按“适配器账号”独立保存与展示；日志列表仍共享；群详情可切换账号查看与修改，旧数据自动兼容。
- **备份稳定性**：修复自动备份偶发“文件被占用”失败。备份不再把旧备份目录递归打进新包，遇到瞬时占用会自动重试，手动与自动备份不会并发执行；失败提示会指明具体文件。
- **群管理权限**：群管理员现在可以执行 `.bot on/off` 开关骰子。OneBot 消息未携带发送者角色时，会从成员信息补查，并兼容 `administrator` 等角色别名；邀请人与群主原有权限保留。
- **默认骰修正**：`.rd-5` / `.r-5` 按“当前默认骰 − 修正”掷骰（默认 100 时即 1d100−5），不再报 `dice sides must be >= 1: -5`。
- **时区统一**：系统设置新增“时区”（默认跟随系统）。跑团日志上传的正文时间、网页导出、审计、备份文件名、定时任务与 `.time` 等统一按配置时区输出；数据库存储仍为 UTC。修复了上传日志正文显示 +0 时区的问题。
- **消息分段**：系统设置新增“消息分段”开关，可整体关闭；QQ 官方机器人、Discord、KOOK 始终不分段；分段发送按顺序并间隔数毫秒，避免客户端乱序。
- **QQ 官方骰主**：添加 Master 时平台可选“QQ 官方机器人”，填入骰主 OpenID 后即可在群聊与私聊中被识别为骰主。
- **QQ 官方群记录修复**：修复官方机器人群事件按 OpenID 产生“已退群”幽灵记录、群内发言后无法重建记录的问题。群事件统一映射到公共群号；启动时自动清理历史幽灵记录；收到群消息时同步清除删除/退群标记。

### 2026-07-29 · builds 753–755

- **可选备份与按天保留**：新增“立即备份到服务器”，不再强制浏览器下载；手动与自动备份统一保存在 `data/backups/`，并使用 `dicenext_bak_YYYYMMDD-HHMMSS.zip`。备份会排除该目录，避免把旧备份递归打进新包。可分别选择系统配置、人物卡与数据库、跑团/运行日志、牌堆规则帮助、JS/Lua 插件及本地媒体；局部恢复仅覆盖所选内容，未选数据不会被清空。自动备份沿用相同选择项，清理策略改为保留最近 N 天而非按份数。
- **已保存备份恢复**：备份列表新增“恢复”操作，可直接选取手动或自动保存的 ZIP 校验并暂存；重启主程序后应用恢复，恢复前的数据仍会保留为回滚副本。

### 2026-07-28 · builds 727–752

- **完整备份与恢复**：旧版 Dice! 数据导入统一迁入“备份恢复”页面；新增 ZIP 格式的本地完整备份下载与恢复上传。备份会先刷新 SQLite WAL，并包含当前配置和全部 `data/` 用户数据，生成后还会校验压缩包；备份现统一保存在 `data/backups/`，均可在面板重复下载或删除。自动备份支持按间隔或每日时刻运行，并按保留数量滚动清理。恢复包仅允许受控路径，校验清单后暂存，下一次启动前再安全替换。恢复前的 `data/` 与配置会自动放入回滚副本，避免运行中覆盖数据库或插件文件。
- **跨骰与自响应防误触发**：修复“骰娘账号自响应时 @ 已登记的其他骰娘，`.r/.ra/.pc` 等代骰类指令反而由自己执行”的漏洞。已登记骰娘目标现在优先于代骰参数和 JS 插件例外处理，明确 @ 其他骰娘将始终静默；正常 @ 玩家代骰、同时 @ 本骰或 @全体不受影响。
- **DND `.rdc` 兼容修复**：支持原版紧凑语法 `.rdc3#+1d4力量 15` 及空格写法；附加骰表达式每轮独立掷出，属性按调整值、技能按独立检定加值叠加。回执改为完整算式和阈值比较，如 `D20+1D4+5=18+3+5=26>15 成功`；`.rdc` 帮助同步更新。
- **Windows 发行管理器**：Windows 包改为顶层 `dice-next.exe` 管理器、`app/dice-next-core.exe` 服务核心和集中式 `lib/` 运行库。管理器本身不依赖包内 DLL，直接双击即可启动 core 并继承控制台日志；更新时会复制出临时维护器，待原进程退出后替换包括 `dice-next.exe` 自身在内的完整程序文件，生成回滚目录。设置 `DICENEXT_UPDATE_RESTART=NO` 后，更新完成只退出，不会自行重启 core，适配 MCSM 等进程托管面板。

### 2026-07-27 · build 726

- **定时任务触发方式扩展**：新增「按间隔（每 N 分钟，1–10080）」与「单次（指定日期+时刻，执行一次后自动停用；停机跨过当天则标记过期不补发）」两种触发方式，与原有「每日定时+星期」并列；新建间隔任务从保存时起算一个间隔后首发，修改触发定义会自动重新对表。列表新增「下次执行」列（每日/间隔/单次分别按规则估算）。
- **自定义回复搜索修复**：规则列表搜索现覆盖全部触发条件与全部回复内容（此前多条件规则只能搜到第一条）。

### 2026-07-27 · build 725

- **回复引擎并发加固**：自定义回复与因果规则的内存规则表改为「不可变快照 + 原子替换」——此前网页保存规则触发重载的瞬间，若恰有群消息在匹配，存在数据竞争隐患；现已彻底消除（并发压测通过）。
- **触发限制补全（对齐原版）**：自定义回复新增「每日上限（按窗口计，可设限额提示语）」「冷却提示语（冷却中回一句而不是沉默）」「用户范围（仅指定用户 / 排除指定用户）」；旧版导入同步支持 `limit` 串中的 `today`、`cd@echo`、`user_id`。匹配测试面板可展示提示语回复与「今日已达上限」等跳过原因。
- **不活跃退群并入定时任务**：原「系统设置 · 群不活跃上限」写死每天 04:00 的独立逻辑，现自动迁移为定时任务页一条「全部群（*）」任务——可见、可改时刻/天数/告别语、可停用、可立即执行（尊重条件）；定时任务目标号码支持填 `*` 表示全部群（逐群评估条件后执行）。
