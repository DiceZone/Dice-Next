# 团务列表分页

团务管理与日志管理均由服务端筛选、排序和分页。WebUI 每页显示 20 条，保留原有分页栏、相邻页切换及跳页输入框。两个选项卡各自保存当前页；修改搜索或排序时回到第一页，删除导致末页消失时自动返回最后一个有效页。

## 搜索与排序

团务支持搜索团名、团号、接入群的群名 / 群号、GM 和玩家。搜索针对全部团务，不限当前页；`%`、`_`、引号等按普通文本查找，不是 SQL 通配符。英文按不区分大小写匹配，中文按文本匹配。

默认按进行中优先排列，同状态按团号稳定排序。可选择团名、团号、状态、创建时间或日志数量，并切换升降序。团务创建时间仍取已关联日志的最早记录时间；无日志时保持为空，不编造开团时间。

## 接口

`GET /api/game-sessions?page=1&size=20&sort=status&dir=desc&q=关键词`

| 参数 | 说明 |
| --- | --- |
| `page` | 从 1 开始，超过末页自动收敛到末页；空列表返回第 1 页 |
| `size` | 默认 20，限制在 1–100 |
| `q` | 可选，去除首尾空白后的文本搜索 |
| `sort` | `status`、`name`、`code`、`createdAt`、`logCount`；未知字段按状态排序 |
| `dir` | `asc` 为升序，其余值使用降序 |

返回标准成功信封中的 `data`：

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "size": 20
}
```

`items` 保留原有团号、团名、GM、玩家、接入群及群名、创建时间、日志状态统计、是否进行中等字段。未提供 `page` 时保留旧版数组响应，供旧客户端兼容；新版 WebUI 始终请求分页接口，不会因分页失败退回全量加载。前后端应配套更新。

## 实现边界

- 活动团务仍使用原有 Lua 配置索引，不迁移存储格式。一次查询只读取索引指向团务的名称、接入群、GM、玩家，不读取牌堆或其他大型插件变量。
- 活动团务和日志恢复的已结团团务在 SQL 中合并、去重、计数、排序及 `LIMIT/OFFSET`。仅处理日志元数据，不读取日志消息、缓存图片或导出文件。
- 无搜索时仅查询当前页相关群名；按群名搜索时先查询全部候选群号和缓存群名，以免漏掉其他页的匹配项，不会调用平台接口实时拉群列表。
- 结团、删除、导出和上传仍以团号操作整个团务，不会只处理当前页。删除团务继续保留日志；删除日志后同时刷新团务统计。
- 前端忽略旧筛选 / 旧页的迟到响应，切换页面或离开后台后，旧操作完成回调不会重新加载旧列表。

本地已使用 2,507 个团务（含 2,100 个活动团务）验证分页、合并和全局检索；不将本机查询耗时视为用户机器或实际部署的性能保证。验证范围见 `server/tests/TEST_REPORT.md`。
