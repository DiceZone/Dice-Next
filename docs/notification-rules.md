# 通知规则

在「系统设置 → 通知设置」管理。支持卡片／列表视图、关键词搜索和服务端分页。
会话显示用户或群组头像、缓存昵称和号码；查不到昵称时保留号码，不重复显示号码作为昵称。

点击页面上方「添加通知规则」，或某条规则的「编辑」打开弹窗；保存按钮位于弹窗顶部。
页面不展开每条规则的事件清单。

## 来源和渠道是两件事

- **监听来源**：所有适配器、指定适配器类型（多选），或指定账号（多选）。
- **程序级通知**：可独立选择是否接收没有具体账号来源的更新、运行错误等通知。
- **发送渠道**：一条规则可以添加多个群聊、私聊、邮件收件人和 Webhook。
- **会话发送账号**：自动模式在目标平台的可用账号中发送一次；也可选择多个发送账号，
  分别发送。指定账号离线时不会回退到其他账号，不会把一个平台的号码发送给另一平台。
- 同一轮通知对同一账号、会话／同一邮箱／同一 Webhook 去重，不因规则重叠重复发送。

## 级别与事件

「按通知级别」使用例行、重要、关键、错误四个区域；「按具体事件」则逐项选择事件。
明确的事件模式中全部取消，或级别掩码为零，都不会自动推送。暂停规则也不会自动推送。
测试通知需确认，且只测试所选规则的渠道；不会因规则暂停或订阅为空而跳过。

旧 Dice! 迁入的 `events: []` 不代表停用：旧数据使用 `level_mask` 过滤。
页面按实际语义展示为「按通知级别」，不再画成全部未勾选。旧数据在读取时映射为规则，
不会在启动时批量改写；首次编辑保存会替换原记录，避免旧、新两份同时发送。
`.notice off` 可移除当前会话的通知渠道，不会删除同条规则中的其他会话或邮件渠道。

## 邮件与 Webhook

新增邮件渠道默认复用权限设置中的身份验证 SMTP：只需填写收件人，不再重复填写主机、
口令等信息。是否发送通知由通知规则控制，不依赖邮箱验证功能的开关。
没有共享 SMTP 时可以回退到已有的通知 SMTP；旧通知的专用 SMTP 保留，可在编辑中明确切换。
Webhook URL 按渠道保存。受限管理员不能修改通知配置，JSON 响应中的 Webhook 密钥地址会脱敏。

邮件、Webhook 仍为后台异步投递；配置测试不等于远端已经接收。实机测试前请核对收件人和地址。
