# 云人物卡自动同步与冲突处理方案

状态：设计稿，**尚未启用自动同步、令牌续期或强制覆盖**。现有手动 `pull / push / sync` 行为保持不变；新增 `.cloud diff 本地卡名` 为只读三方对照。

## 权限与入口

- 骰主只能设置功能是否可用、最低同步间隔和队列上限，不能替玩家开启上传，也不能从管理页读取玩家的 OAuth 令牌或云端私有卡。
- 玩家本人在已授权的原私聊中，为已经关联的单张卡主动选择自动同步。拟议指令为 `.cloud auto <本地卡名> on|off|status`，默认关闭；这些指令目前尚未实现。
- 只读授权只能选择自动拉取；本地有修改则暂停。双向同步必须另获 `cards.write` 授权，并确认本地数据将发往账号中心。不得把“同意读取”当成上传同意。
- 作用域沿用适配器、骰娘账号、平台和原始玩家身份；跨适配器不能复用授权。登出、撤销授权、换 Key、锁卡、身份变更立即停止。

## 调度与一致性

使用已有单工作线程云卡队列，不占适配器消息线程。建议本地修改防抖 30 秒，云端轮询最低 5 分钟，加入随机错峰。每张卡同一时间最多一个任务；手动操作优先，重复修改合并为一次待同步。

每次操作保留三份快照：上次成功同步的基础、本地当前值、云端当前修订。

| 情况 | 处理 |
| --- | --- |
| 两边均未改变 | 不写入、不推进修订 |
| 仅云端改变 | 本地快照和锁仍一致才导入，成功后更新同步基线 |
| 仅本地改变 | 有明确写入授权才上传，以已知 `base_rev` 提交 |
| 两边修改不同字段 | 使用服务端版本协议合并；客户端不擅自丢弃未知字段、数组或元数据 |
| 同字段不同修改 / HTTP 409 | 暂停该卡，私发一次冲突提示，不更新基线，不自动用新修订重试覆盖 |
| HTTP 401 / 失效 | 暂停并提示重新授权，不自动申请权限或续期 |
| HTTP 429 / 网络故障 | 尊重限流并指数退避；首传结果不确定时先核对远端，防止重复创建 |

接收云端响应后，必须再次核对本地快照、读写锁和身份。若请求期间本地被修改，保留新改动，不覆盖、不误报“同步完成”。重启后即使保留了玩家偏好，也须重新授权才能恢复任务，不能持久化现有 OAuth 令牌来绕过这一点。

## 冲突界面

现阶段 `.cloud diff 本地卡名` 在本人私聊列出 JSON Pointer 字段路径和“基础 | 本地 | 云端”三份值，并标注 `local / remote / same / conflict`。只读取，不改卡、不改基线。最多 30 项，长值不截断冒充完整值，提示拉取独立副本。卡片中的 CQ/媒体代码只按字面展示。

下一步的可编辑冲突界面应由玩家自己的账号中心会话承载，而不是骰主 WebUI。按冲突字段选择本地、云端或手动值，同时展示保留的非冲突变更；提交前显示完整结果并明确确认。确认绑定具体本地快照、云端修订、原始身份和短期票据，任何一方再次变化即使旧选择失效，重新对照；不得提供无提示的“全部强制覆盖”。

## 服务端依赖与实施门槛

先核对 BDC 当前修订协议、限流、ETag/增量查询和令牌续期能力，再实现自动同步。若没有 refresh grant，只能暂停并重新授权，不能靠循环设备授权替玩家续期。不在此方案中擅自修改 BDC 服务端。

上线前必须验证：身份与多适配器隔离、授权只读/写入、登出撤销、409 不重试、删除与空值、未知插件字段、锁卡、并发编辑、重启恢复、限流退避、私聊通知失败、退出不遗留任务，以及服务端与本地两边实际修订。纯对照测试通过不代表自动同步已完成。
