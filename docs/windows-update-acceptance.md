# Windows 更新器实机验收

状态：待执行。Mac 本地测试与 Windows CI 的单元测试均不能代替完整发行包的安装验收。

## 测试环境

使用独立 Windows 测试目录和无真实用户数据的测试实例；保留原发行包、测试配置与数据副本。不要在生产骰娘上制造断网、杀进程或文件占用。记录 Windows 版本、架构、源/目标版本、更新源与每次操作时间。管理器与 core 必须来自同一完整发行包。

## 检查清单

- [ ] 正常检查：顶栏版本及 New 与检测结果一致；点击定位更新区域。
- [ ] 连接阶段取消：界面先进入 cancelling，子进程被回收后才显示 cancelled；立即重试不出现并行下载。
- [ ] 下载阶段断网 / 无进度：停滞达到阈值后终止该源并按配置换源，最终失败时仍可操作，无需重启 core。
- [ ] 下载阶段取消：临时部分包被清理，已经校验过的包不被误删；取消后重新下载成功。
- [ ] 校验 / 准备阶段取消：无半成品被标记 ready；错误不会被轮询抹掉。
- [ ] UI 请求超时：仅表示 HTTP 等待结束，不伪装成服务端任务已取消；重新读取状态后继续提供正确操作。
- [ ] 正常安装：installing 不提供取消；管理器退出旧 core、替换包内程序并重启，配置、数据、插件均保留。
- [ ] 管理器自身替换：临时维护器完成顶层 exe 更新，不遗留占用或无限重启。
- [ ] 安装失败 / 文件占用：逆序回滚，可用旧版本重新启动；保留可诊断错误，不丢用户数据。
- [ ] `DICENEXT_UPDATE_RESTART=NO`：更新成功后不自行启动 core，交由外部面板托管。
- [ ] 容器保护：检测允许，下载和安装仍由服务端拒绝，不因新增 UI 操作绕过。
- [ ] 退出清理：慢源下载时退出不等待整段超时；任务、curl 与临时维护器均按预期结束。

每项记录通过/失败、状态变化、日志与截图，隐去口令和令牌。失败项保留测试目录供排查。只有真实 Windows 发行包完成以上检查，才把 roadmap 的实机验收改为完成。
