# 回复正则匹配修正与检测记录

检测日期：2026-10-13。本地环境：Windows / MSVC，Release 构建。

## 结论与原因

用户表达式 `^白(丽|麗).{0,6}` 应限制整条消息，而不是只检查消息开头。旧 Dice 的 `DiceMsgReply.cpp` 使用 `std::regex_match`；Next 的基础回复曾使用开头匹配，因果规则曾使用局部搜索。差异在早期实现中已经存在，不能归因于最近的正则超时保护。

整条匹配与局部搜索都是正常的正则调用方式；本次选择整条匹配，是为了统一回复规则并恢复旧 Dice 的使用习惯，不是宣称局部搜索“不符合标准”。两种调用的区别见 [Microsoft 正则函数说明](https://learn.microsoft.com/en-us/cpp/standard-library/regex-functions?view=msvc-170#regex_match)。

## 已修正的链路

| 入口 | 修正后行为 |
| --- | --- |
| 基础回复匹配、数据库重载、候选与试匹配 | 忽略大小写，匹配整条消息 |
| 基础回复变量渲染 | 与匹配阶段共用相同引擎、模式和长度限制 |
| 因果规则正式执行、已保存规则试匹配、草稿试匹配 | 同样整条匹配，并保留实际条件的捕获结果 |
| 因果回复实际发送、网页测试回复 | 使用匹配时的捕获，不再次匹配，不把捕获内容重新解释成模板 |
| Lua 旧 Mod 的 Regex 条件 | 保留原本的整条匹配，补齐分支与懒惰量词回溯 |
| 两种网页试匹配输入 | 保留首尾空白，可输入换行；只有用户、群等上下文 ID 会 trim |

字面前缀匹配、字面包含匹配仍是独立功能。插件自身的 JavaScript 正则 API、程序内部用途明确的搜索与替换没有被整体改写；回复配置没有增加第二种正则模式。

## 同时排除的语义缺口

- **分支选择与回溯**：不能只取 `RegExp.exec` 的第一个结果再比较长度。例如 `a|ab` 对 `ab` 应可回溯至第二分支，`a+?` 应可扩展至消息末尾。现在用不增加捕获编号的分组包裹，并把严格末尾约束放入同一次匹配。
- **严格末尾与换行**：约束真正的输入末尾，避免遗漏尾部换行；`.` 默认不跨行，`[\s\S]` 可跨行。原表达式先单独验证语法，防止包装意外修复非法括号或转义。
- **捕获分组**：保留未参加分支的空捕获、正确编号、中文和嵌入的 NUL。OR 取真正命中的条件，AND 优先取第一条正则条件；冷却跳过或匹配失败的规则不能泄漏捕获。非 `u` 模式若把 emoji 拆成孤立代理单元，输出以 U+FFFD 替换不可表示的半个字符，完整 emoji 不变，保证捕获可安全序列化为 UTF-8 JSON。
- **模板安全**：用户捕获内容里的 `{sample:…}`、`{roll:…}`、牌堆引用等只是文字，不会作为新模板执行。
- **前端一致性**：基础回复粗验按 400 **UTF-8 字节**计数，不再按 JavaScript 字符串长度误判。浏览器只验语法，实际匹配交给后端，避免在页面执行不可信正则。

## 回归覆盖

新增定向用例覆盖原报告的简繁汉字、0–7 个尾部字符、分支与懒惰量词、空捕获、反向引用、前后查找、字符类、转义、命名捕获、空输入、空白、五类换行、NUL、emoji、大小写、非法表达式、长度上限、模式缓存隔离与超时熔断后的健康表达式恢复。

共同 ECMAScript 子集交叉对照：30 个表达式 × 163 个输入 × 整条 / 开头 / 搜索三种内部模式。Windows 实际比较 **14,664** 组，包含全部 **4,890** 组整条匹配及其捕获结果。MSVC 部分搜索模式对换行锚点的六组平台差异不拿来作为 JavaScript 方言的判定依据；另用明确的 ECMAScript 预期检查，未忽略整条匹配组合。语义依据为 [ECMAScript RegExp 执行规则](https://tc39.es/ecma262/2025/multipage/text-processing.html#sec-regexpbuiltinexec)。

集成用例使用真实数据库、ReplyManager、CausalRuleManager、CommandRouter 和 Lua 加载器，检查重载、AND/OR、试匹配不消费冷却、实际捕获输出及捕获模板隔离。前端执行真实组件的请求逻辑，用模拟时钟与请求替代网络，不启动监听服务。

## 兼容与安全边界

- 新规则统一整条匹配，无需手动加 `^` / `$`。`白(丽|麗).{0,6}` 在第七个尾部字符时不触发。
- 已有 Next 规则若依赖开头或局部匹配，需显式写 `abc.*` 或 `.*abc.*`。程序不擅自重写保存的表达式；旧 Dice 原本的整条匹配规则无需补 `$` 或重新导入。
- 保持 ECMAScript `i` 模式，不自动启用 `u`、`m`、`s`，不声称支持全部 PCRE、POSIX 或 C++ locale 扩展。非 `u` 模式量词按 UTF-16 单元计数，常见汉字为 1，许多 emoji 为 2，不按视觉字形计数。
- 保持既有限制：基础回复表达式 400 UTF-8 字节；共享引擎表达式 4096 字节、输入 64 KiB，最多导出含整条匹配在内的 1024 项捕获；Lua 旧 Mod 仍有 400 字节输入限制。因果规则沿用共享引擎上限，没有借统一匹配模式缩减既有长度限制。
- 保留每次至多 100 毫秒执行预算、16 MiB 内存、512 KiB 栈、有限缓存与超时熔断；嵌套在插件调用时不会重置外层时间预算。
- 有限回归测试不是对全部可能正则的数学证明；本轮尚未在 Linux/macOS 上运行，也未模拟真实平台消息发送。
