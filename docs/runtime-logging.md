# 程序运行日志

程序日志用于排查启动、插件、配置、接口和后台任务的问题，与 `.log` 生成的跑团记录分开保存。

## 文件与格式

- 文件位于运行目录的 `data/logs/app/`。每次启动使用新文件名，包含启动时间和进程号；跨午夜按日切分。
- 时间使用服务器本地时区，并显示 `tz` 偏移。例如 `tz=+0800` 表示 UTC+8，不代表浏览器时区。
- 文件保留日期、级别、记录器三个原有字段，WebUI 首页仍能读取级别和多行内容；随后追加线程号与源码文件、行号。
- 控制台使用较短的时间格式和彩色级别。多行堆栈以 `    | ` 缩进，控制字符会转义；过长的单条内容会截断并标记 `[truncated]`。

示意：

```text
[2026-10-12 12:34:56.789] [error] [dice] [tz=+0800 thread=42] [js_plugin_manager.cpp:123] [js] command='demo' error: Error: example
    |     at inner (demo.js:8)
    |     at solve (demo.js:12)
```

## 新增诊断

- 管理接口记录方法、路径、请求编号、结果和耗时。HTTP 200 中的业务失败也会记录，避免页面提示失败但文件完全没有线索。API 响应附带 `X-Dice-Request-Id`，可用来对应同一次操作。
- 管理修改记录 `phase=begin/end`；Lua、JS 和规则重载额外记录获得锁等阶段。单文件插件执行前记录文件名，加载结束记录结果。只有开始没有结束，说明该阶段尚未完成，**不单凭这一点判断为死锁**。
- JS 加载、命令、消息/事件钩子、定时器和异步任务错误保留可用的堆栈；Lua 受保护调用和协程错误保留 traceback。
- 补齐消息/事件处理器、AI 工作线程、聊天记录存储、配置监听回调、首页日志读取等此前吞掉异常的路径。C++ 标准异常保留原因链，非标准异常也有明确记录；这里不是所有平台的原生崩溃转储。
- 错误通知仍每 60 秒只推送首条；其余错误保留在文件中。推送延后到事件循环，避免写日志时占用配置、插件等锁再去发送通知。通知本身出错也会记录，并避免递归通知造成卡死。

## 级别与隐私

`config/server.json` 的 `log_level` 默认是 `info`，可选 `trace`、`debug`、`info`、`warn`、`error`、`critical`、`off`。配置更新后会同步日志级别。正常页面轮询和指令预览的 HTTP 成功记录放在 `debug`，避免默认刷屏；超过 2 秒的 API 调用会记录慢请求警告。参数或业务校验失败通常为 `warning`，服务器故障为 `error`。

新增 HTTP 诊断不记录请求正文、查询参数、认证头或成功响应数据。日志输出统一屏蔽常见密码、令牌、密钥字段及配置中已知的凭据，JSON 解析错误中的输入片段也会移除。但插件自己打印的任意个人数据、既有消息日志和未知字段无法保证全部识别，**发送诊断日志前仍需检查并遮盖敏感内容**。

日志目录不能写入时，程序保留控制台输出并报告文件输出失败。启用 `off` 会关闭常规日志，不建议在排查期间使用。

## 本地回归

`tools/test-plugin-reload.mjs <core-binary> [lua-file]` 使用临时数据、回环监听和独立 API 密钥，不连接机器人或外部服务。它验证插件上传、启停、删除、并发重载和正常退出，也会主动触发 JS/Lua 错误，检查实际日志文件、首页读取和密钥脱敏。该驱动仅测试 POSIX 正常退出，不代替 Windows 托盘实测。

增加 `--reliability` 可运行死循环、超时恢复和大日志读取的故障注入。执行预算、暂停与兼容性变化见[故障保护说明](runtime-reliability.md)。
