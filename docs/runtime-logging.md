# 程序运行日志

程序日志用于排查启动、连接、插件、消息、设置和后台任务的问题，与 `.log` 跑团记录及通知审计分开保存。

## 四个主字段

控制台与普通日志统一为 **时间、级别、模块、内容**：

```text
[2026-10-12 10:20:31.102] [INFO] [消息] 收↩ [onebot_v11「正向 WS」] [群 内测群(933145116)] 希亚(1707642)：.求签
[2026-10-12 10:20:31.115] [INFO] [处理] Lua 插件「求签」（draw）；结果：处理完成，生成 1 条回复；触发：用户消息：.求签；拟发送至：群 933145116；拟发送内容：**希亚**抽到了上签。 (msgID:示例会话-123)
[2026-10-12 10:20:31.119] [INFO] [消息] 发↪ [OneBotV11「正向 WS」] [群 933145116] 骰娘：希亚抽到了上签。；已提交发送，等待平台结果 (msgID:示例会话-123)
```

上例是格式示意，不是真实发送记录。时间包含毫秒，按程序的服务器时区设置输出，首页不再按浏览器时区重算。时区在日志会话开始时说明，不重复附在每条记录上。

C++ 文件、行号、函数与线程号不占普通前缀，保留在结构化诊断记录及首页的“诊断详情”中。JS/Lua 错误保留真实脚本堆栈。模块由埋点的子系统或显式字段指定，不从用户消息猜级别或插件名称。

## 六级与筛选

| 级别 | 用途 |
| --- | --- |
| TRACE | 高频协议跟踪，例如正常 OneBot 心跳 |
| DEBUG | 轮询、缓存、匹配和执行阶段等排查细节 |
| INFO | 收发消息、处理结果、设置变更等正常事实 |
| SUCCESS | 重要操作已确认完成或状态已恢复 |
| WARN | 问题仍可重试、降级或部分完成 |
| ERROR | 本次操作已失败或功能不可用 |

顺序为 **TRACE → DEBUG → INFO → SUCCESS → WARN → ERROR**，默认 INFO，包含 INFO、SUCCESS、WARN、ERROR。玩家检定失败或大失败不属于程序 ERROR；提交更新、启动连接、生成回复也不等于已经完成安装、连接或送达。

- **最低记录级别**：WebUI 设置 → 控制台日志，立即控制新产生的控制台与文件记录，对应 `server/log_level`。
- **最低展示级别**：首页最近日志的筛选器，保存在当前浏览器，不修改机器人设置。
- 降低展示阈值不能补出过去未保存的 DEBUG/TRACE；排查前应先降低记录级别。
- 旧配置中的 `warning` 映射 WARN，`critical/fatal/err` 映射 ERROR；`off` 配置兼容但不在六级选择框中推荐。旧式接口字段继续兼容。
- 协议事件诊断开关不再把正常心跳或接口轮询提升至 INFO，仍遵守对应记录阈值。

## 处理来源与 msgID

`[处理]` 记录处理者、触发方式、结果、目标与拟发送内容；`[消息]` 保留平台格式化后的实际提交内容，不再重复处理来源。平台操作另用 `[事件]`，同样可关联。

内部 msgID 含本次进程的随机会话标识与递增序号，不是平台消息 ID，不在每次重启后简单复用。独立输出各有 ID；长回复分段和格式回退重试保留原 ID，并标注分段。向不同目标发送的独立输出各自建计划。平台响应采用 DEBUG 确认接受，最终失败采用 ERROR；失败记录仍在诊断字段中保留同一 ID，但简短错误正文不再重复整条消息和 ID。网络失败时不能据此证明用户没有收到。

首页可搜索模块、插件、内容或 msgID，点击“查看关联记录”查看同一 ID 的记录，不受列表展示阈值限制。失败记录的诊断本身也保存来源，原 INFO 计划未记录或已超出近期窗口时仍可查到处理者。

来源覆盖内置指令、快捷指令中的插件、JS/Lua 回复、高级回复、因果规则、定时任务与系统事件。混合回复保留贡献来源；异步、定时和 Lua sleepTime 会携带来源。JS 主动日志与发送还核对实际执行脚本的文件，避免跨插件 Promise 续跑误标为唤醒它的插件。无法可靠识别时明确说明，不猜成最近执行的插件。

插件执行中主动发送记为“请求发送”，不提前宣称整个插件成功。未完成的 Promise 会显示异步等待；执行失败但先前已生成的内容保留真实结果。无文本回复的指令可记处理结果，不伪造发送记录。

## 插件主动日志

- Lua `log(...)` 与 `print(...)` 保持 INFO；增加 `logTrace/logDebug/logInfo/logSuccess/logWarn/logError(...)`。
- JS `console.log/info` 对应 INFO，`console.warn` 对应 WARN，`console.error` 对应 ERROR，`console.debug/trace` 对应 DEBUG/TRACE。
- 插件主动日志用 `[插件]`，包含已知插件名称/脚本来源；其内容是插件自己报告的事实，不替代宿主的执行和发送结果。
- 普通插件日志不强行分配 msgID，只有属于具体发送链的诊断才关联该输出。

## 保存与隐私

运行目录 `data/logs/app/` 同时保存按启动会话及日期命名的可读 `.log` 和结构化 `.jsonl`。后者含级别、模块、来源、关联 ID 和诊断详情；两者都脱敏。首页读取当前进程的有界近期记录，最多保留 1000 条、返回最近 500 条，不按每次轮询重扫整天日志。

密码、密钥、Token、Cookie、认证头、URL 认证和已知签名参数屏蔽；所有级别都遵守。换行以续行缩进保存，控制字符转义，过长记录截断并标记；异常字节替换为有效 UTF-8，不能把插件日志变成 JSON 序列化崩溃。AI 调试日志不再复制提示词、用户上下文和完整响应正文。

未知个人信息仍无法保证全部自动识别，分享诊断前应人工检查。文件写入失败会报告可用输出的限制。原生崩溃仍单独保存 `data/logs/crash_*.txt`，不能保证崩溃时普通日志器可继续工作。

错误通知使用业务短句，保留实际解释器／平台错误和必要对象，不展开整套诊断字段。通知投递失败只记本地日志，异步平台回调也不会重新生成错误通知；相同目标与原因一分钟合并，防止故障时刷屏。正常 INFO 收发内容不受影响，详见 [通知规则](notification-rules.md)。不改变通知订阅、bot off、权限、定时任务和平台路由策略。

## 验证

日志回归覆盖六级阈值、旧级别兼容、独立 SUCCESS、四字段格式、详情留存、脱敏与异常字节、msgID 的拟发送/实际内容/失败关联、嵌套上下文恢复、Lua/JS 自报级别及延时来源、跨插件 await 续跑来源。

JS 指令、初始化回调和定时回调返回拒绝的 Promise 时按 ERROR 记录，不误报执行完成；已生成的回复仍保留。异步等待、部分加载失败与后续回调异常分别标明，不等同于平台发送失败。

`tools/test-plugin-reload.mjs <core-binary> [lua-file]` 使用独立临时数据和回环 API，验证重载、异常堆栈、近期记录与结构化诊断脱敏；`--reliability` 增加超时与大日志故障注入。此驱动的 POSIX 正常退出检查不代替 Windows 托盘验收。

`tools/test-runtime-logs.mjs <core-binary>` 使用隔离的实际 core 与本地模拟 OneBot 验证收发链路；不连接真实账号。在 Windows 上默认拒绝启动，只有明确同意后加 `--allow-windows-listener` 才运行。测试复制的程序开启本地监听时可能触发 Windows Defender 防火墙弹窗，无需为测试放行，也不会自动修改防火墙。
