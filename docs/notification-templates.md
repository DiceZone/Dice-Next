# 骰主通知模板全览（审阅稿）

核对日期：2026-10-25。对应本轮本地实现，不代表已经提交、推送或发布。

范围：全部内置订阅事件、同一事件的不同结果、运行错误通用模板，以及不再外发的通知投递错误。插件可以提供任意错误原文或自定义通知，本文列出其包装规则，不虚构所有插件可能出现的报错。

## 一、统一规则

格式是 `[发生了什么] 内容`。不再固定堆砌时间、级别、模块、线程、源码位置、日志 ID、msgID、诊断字段，也不把失败消息全文嵌套回来。确有帮助的解释器行号和平台错误原因保留。

| 占位符 | 实际示例与回退 |
| --- | --- |
| `{群}` | `群未归星璇(792364383)`；无群名为 `群(792364383)` |
| `{用户}`、`{操作者}` | `小明(3569827618)`；无昵称为 `用户(3569827618)` |
| `{管理操作人}` | `希亚(1707642)`；插件为 `插件「群管助手」`；密码／API 登录且无可核实 QQ 身份为 `面板操作人（未提供可核实的昵称和帐号）`；系统操作为 `系统` |
| `{适配器}` | `OneBot:3626455591`；无帐号时用平台和适配器名称，不拿内部编号冒充平台帐号 |
| `{原因}`、`{错误原文}` | 实际策略原因或底层错误；不推测“哪个标点写错”等未经证实的根因 |

正文没包含的相关群、用户、目标、适配器，会在末尾补一行。例如：

```text
[骰娘被踢出群聊] 骰娘被小明(3569827618)踢出群未归星璇(792364383)。
适配器 OneBot:3626455591
```

同一帐号／群号不重复补充；骰娘自己不再列为“用户／操作者”。优先使用事件信息、来源帐号缓存，再查持久化记录。缓存名称可能不是此刻的最新名称；获取不到时保留帐号，不编造昵称。

敏感字段脱敏，身份验证指令隐藏；CQ 动作码文本化，不能借通知触发 @全体 等动作。过长内容截断并提示查看后台日志／发布页。以下“原因／附言”为空时均省略整行。

### 通知级别与程序日志级别不同

| 通知级别 | 值 | 用途 |
| --- | --- | --- |
| 例行 | 1 | 日常管理变更 |
| 重要 | 2 | 好友／群关系、退群、任务、更新等业务事件 |
| 关键 | 4 | 骰娘管理权限、名单操作 |
| 错误 | 8 | 运行、更新、退群提交异常 |

可相加，例如 10 为重要＋错误，15 为全部。TRACE／DEBUG／INFO／SUCCESS／WARN／ERROR 是运行日志的显示过滤，不是这里的订阅级别。

## 三、群关系和权限

下面均为重要通知。平台未提供的事件不伪造；普通成员的所有变动不默认广播给骰主。

### 离群结果 `group_left`

| 实际事件／条件 | 通知内容 |
| --- | --- |
| 明确被踢／被移除，知道操作者 | `[骰娘被踢出群聊] 骰娘被{操作者}踢出{群}。` |
| 明确被踢，操作者缺失 | `[骰娘被踢出群聊] 骰娘被群管理员（平台未提供操作者）踢出{群}。` |
| 明确群解散，知道操作者 | `[群聊已解散] {群}已被{操作者}解散，骰娘已离开该群。` |
| 明确群解散，操作者缺失 | `[群聊已解散] {群}已解散，骰娘已离开该群（平台未提供操作者）。` |
| 明确主动退出，匹配近期请求 | `[骰娘退群已确认] 平台已确认骰娘退出{群}；此前由{请求来源}发起退群。`，有原因再加一行 `原因：{原因}` |
| 明确主动退出，没有匹配请求 | `[骰娘主动退出群聊] 骰娘主动退出{群}；未关联到本程序近期提交的退群请求，可能来自其他客户端或已失效的历史请求。` |
| 没有可靠的退出类型 | `[骰娘离群（原因未知）] 骰娘已离开{群}；平台未提供明确的离群原因，无法确认是被踢还是主动退出。` |

原因未知时，确有操作者则补 `平台上报的操作者：{操作者}。`；确有近期请求则补 `此前曾由{请求来源}提交退群请求，但不能据此认定本次离群原因。`。

明确的被踢／解散回执优先级最高，不会因为此前有 `.dismiss` 就归因成指令请离。不能仅凭“有操作者”推断被踢。

请求关联只匹配同一适配器、平台、群最近 5 分钟的记录，数量有上限，消费一次即移除，不跨进程保存。因此重启后的历史请求不会被猜作本次原因。

### 已入群 `group_joined`

条件：平台确认骰娘入群，启用了新群事件处理；不是收到邀请就算入群。

```text
[骰娘已加入群聊] 骰娘已加入{群}。
邀请／批准人：{用户}。
```

邀请人缺失时第二行改为 `平台未提供邀请／批准人。`。立即被既有规则判定自动退群的入群事件可进入对应退群分支，不强行输出欢迎结果。

### 禁言 `group_ban`

条件：被操作对象是本帐号，或平台明确报告全体禁言。时长按天／小时／分钟／秒组合，如 `1天1小时1分钟1秒`。

| 情况 | 文案 |
| --- | --- |
| 本帐号被禁言 | `[骰娘被禁言] 骰娘在{群}中被{操作者}禁言{时长}。` |
| 本帐号解除禁言 | `[骰娘禁言已解除] 骰娘在{群}中被{操作者}解除了禁言。` |
| 全体禁言开启 | `[群已开启全体禁言] {群}已由{操作者}开启了全体禁言。` |
| 全体禁言关闭 | `[群全体禁言已解除] {群}已由{操作者}关闭了全体禁言。` |
| 禁言类型缺失／无效 | `[群禁言状态变更] {群}的禁言状态发生变化；平台未提供禁言或解除禁言的明确类型。` |

操作者缺失：省略 `{操作者}`／`由{操作者}`，句末加 `（平台未提供操作者）`。时长无效：使用 `（平台未提供有效时长）`，不猜为 0 秒或永久禁言。

### 群管理员 `group_admin`

条件：平台报告本帐号管理员权限变化，不是骰娘系统管理权限。

```text
[骰娘获得群管理权限] 骰娘在{群}中被{操作者}设为管理员。
[骰娘群管理权限被取消] 骰娘在{群}中被{操作者}取消了管理员权限。
```

操作者缺失：省略其姓名帐号，句末加 `（平台未提供操作者）`。

设置／取消类型无效时：

```text
[骰娘群管理权限变更] 骰娘在{群}中的管理员权限发生变化；平台未提供设置或取消的明确类型。
```

## 四、好友与群审批

均为重要通知。审批接口没有立即抛错只代表“已提交”，不等于平台已经同意或关系已经建立。附言为空不显示。

### 固定正文

| 事件 | 文案 |
| --- | --- |
| `friend_req` | `[好友申请] 收到{用户}的好友申请。` |
| `group_invite` | `[加群邀请] 收到{用户}邀请骰娘加入{群}。` |
| `group_request` | `[群成员入群申请] 收到{用户}加入{群}的申请。` |

上述三类均追加：

```text
处理：{决定}（{依据}）。
附言：{实际附言}
```

### 好友审批分支

| 条件 | 决定 | 依据 |
| --- | --- | --- |
| 允许所有申请 | 已提交自动同意 | 当前好友策略允许所有申请 |
| 好友关键词命中 | 已提交自动同意 | 附言命中好友验证关键词 |
| 好友关键词不命中 | 等待人工处理 | 附言未命中好友验证关键词，未提交审批 |
| 符合好友白名单 | 已提交自动同意 | 申请人在好友白名单中 |
| 不符合好友白名单 | 等待人工处理 | 申请人不在好友白名单中，未提交审批 |
| 有群聊使用记录 | 已提交自动同意 | 申请人有群聊指令使用记录 |
| 无群聊使用记录 | 等待人工处理 | 未找到申请人的群聊指令使用记录，未提交审批 |
| 非黑名单策略，未命中黑名单 | 已提交自动同意 | 申请人不在黑名单中 |
| 非黑名单策略，命中黑名单 | 等待人工处理 | 申请人在黑名单中，按当前策略保留人工处理 |
| 禁止添加好友 | 已提交自动拒绝 | 当前好友策略禁止添加 |
| 人工审批 | 等待人工处理 | 当前为人工审批模式，未提交同意或拒绝 |

### 群邀请审批分支

| 条件 | 决定 | 依据 |
| --- | --- | --- |
| 拒绝黑名单群策略命中 | 已提交自动拒绝 | 目标群在黑名单中 |
| 拒绝非好友邀请策略命中，且不豁免 | 已提交自动拒绝 | 邀请人不是好友，且开启了拒绝非好友邀请 |
| 允许所有邀请 | 已提交自动同意 | 当前群邀请策略允许所有邀请 |
| 白名单策略符合 | 已提交自动同意 | 邀请人为骰主或在白名单中 |
| 白名单策略不符合 | 等待人工处理 | 邀请人不是骰主且不在白名单中，未提交审批 |
| 拒绝邀请 | 已提交自动拒绝 | 当前策略禁止接受群邀请 |
| 手动／不自动处理 | 等待人工处理 | 当前策略不自动处理邀请，未提交同意或拒绝 |

申请阶段拒绝非好友属于 `group_invite`；已经被直接拉入群再退出才属于 `nonfriend_leave`。

### 群成员申请审批分支

| 条件 | 决定 | 依据 |
| --- | --- | --- |
| 本群 auto pass 为 all | 已提交自动同意 | 本群 auto pass 允许所有申请 |
| 本群 auto pass 关键词命中 | 已提交自动同意 | 附言命中本群 auto pass 关键词 |
| 本群 auto pass 关键词未命中 | 等待人工处理 | 附言未命中本群 auto pass 关键词，未提交审批 |
| 本群未配，且全局未自动审批 | 等待人工处理 | 未开启群成员申请自动审批，未提交同意或拒绝 |
| 全局自动审批，无关键词 | 已提交自动同意 | 已开启群成员申请自动审批 |
| 全局自动审批，关键词命中 | 已提交自动同意 | 附言命中群成员验证关键词 |
| 全局关键词未命中 | 等待人工处理 | 附言未命中群成员验证关键词，未提交审批 |

### 旧模组审批钩子分支

覆盖同一申请的决定／依据，不放宽原有骰主策略：

| 情况 | 决定 | 依据 |
| --- | --- | --- |
| 插件明确拒绝且接口调用没有立即失败 | 已提交自动拒绝 | 插件审批明确拒绝；等待平台处理结果 |
| 插件接管但没有可执行审批决定 | 等待人工处理 | 插件阻止了自动审批，未提交同意或拒绝 |
| 插件审批失败 | 等待人工处理 | 插件审批钩子执行失败，未提交同意或拒绝 |
| 插件请求同意但主策略不允许 | 等待人工处理 | 插件请求同意，但骰主的审批策略不允许自动通过，未提交同意或拒绝 |

接口抛错时进入运行错误，不再输出虚假审批成功。关闭好友／群请求事件处理时，不处理申请，也不生成对应业务通知。

### 已成为好友 `friend_add`

条件：实际收到平台新好友事件，启用了对应监听，且未被旧插件钩子接管。

```text
[新好友已添加] 已与{用户}成为好友。
```

QQ 官方首次出现且无历史昵称的 OpenID 会显示为 `用户(OpenID)`；已有昵称才复用，不假称此事件提供了昵称。

## 五、退群请求

下面均为重要通知；只是提交请求，收到平台回执后才使用第三节的结果。

```text
[退群请求已提交] {请求来源}请求骰娘退出{群}；退群请求已提交，等待平台确认。
原因：{原因}
```

| 事件 | 条件 | 请求来源 | 原因 |
| --- | --- | --- | --- |
| `dismiss` | 有权限的 `.dismiss` 延迟到期，真正调用接口 | `{操作人}通过指令 .dismiss` | 通常为空 |
| `leave` | 群管理面板退群 | `{管理操作人}通过管理面板` | 通常为空 |
| `leave` | 定时退群动作 | `定时任务「{任务名}」` | 配置的退群说明 |
| `blacklist_leave` | 入群时目标群在黑名单 | `黑名单群自动退群` | 目标群在黑名单中 |
| `blacklist_leave` | 既有黑名单成员规则命中 | `黑名单成员入群规则` | 黑名单用户{用户}加入了本群 |
| `nonfriend_leave` | 非好友直接拉群且策略要求退出 | `拒绝非好友邀请规则` | 非好友{用户}将骰娘拉入群 |
| `keyword_leave` | 已取得群名且关键词命中 | `群名关键词规则` | 群名「{名称}」包含关键词「{词}」 |
| `group_size_leave` | 入群后人数超限 | `群规模上限规则` | 当前群规模 {人数} 人，超过上限 {上限} 人 |
| `group_auto_clean` | 周期清理发现人数超限 | `定期群聊清理` | 群规模 {人数} 超过上限 {上限} |
| `group_auto_clean` | 周期清理发现符合退群策略的黑名单成员 | `定期群聊清理` | 存在黑名单用户 {帐号} |
| `usergroup_leave` | 必须加入用户群的检查失败 | `必须加入用户群规则` | 本群成员与要求加入的用户群{群号}没有交集 |

好友列表未知不直接判为非好友，群名未知不判关键词命中。本轮不增加自动拉黑／邀请人连坐。

### 退群提交失败 `leave_error`，错误

```text
[退群请求失败] {请求来源}请求骰娘退出{群}失败：{原因}。
```

| 条件 | 原因 |
| --- | --- |
| 目标缺失 | 未提供群帐号，未提交退群请求 |
| 来源适配器不存在／离线 | 来源适配器未连接，未提交退群请求 |
| 适配器不支持退群 | 此适配器不支持主动退群，未提交退群请求 |
| 接口抛出异常 | 原始异常内容 |
| 未知异常 | 退群接口抛出未知异常 |

只在真正走到提交器时生成这条通知；事先被权限／参数校验拒绝的操作直接向页面／当前窗口返回失败，不广播为已执行操作。提交失败撤销关联请求；`.dismiss` 的退群中标记解除，不阻塞群后续消息。

## 六、权限与名单

| 事件、级别、条件 | 通知模板 |
| --- | --- |
| `trust`，例行，有权限者设置信任等级；查询不通知 | `[信任等级变更] {管理操作人}：已将{用户}的信任等级从 {原等级} 调整为 {新等级}。` |
| `admin`，关键，授予骰娘管理权限 | `[管理权限变更] {管理操作人}：已授予{用户}骰娘管理权限。` |
| `admin`，关键，收回骰娘管理权限 | `[管理权限变更] {管理操作人}：已收回{用户}的骰娘管理权限。` |
| `alias`，例行，帐号权限关联新增／替换 | `[帐号别名变更] {管理操作人}：已绑定账号别名 {别名帐号} -> {主帐号}` |
| `alias`，例行，解除帐号权限关联 | `[帐号别名变更] {管理操作人}：已解除帐号别名 {别名帐号} 的绑定。` |

这里 `alias` 是 `.admin account-alias` 的权限关联，不是海豹式快捷指令 `.alias`。

### 名单变更 `blacklist`，关键

条件：指令、面板、JS 插件 `seal.ban` 真正新增／移除条目。重复添加／删除不存在条目不重复通知；云黑批量同步与初始化不因此逐条广播。

```text
[黑名单变更] {管理操作人}：已将{用户或群}加入黑名单。
原因：{原因}
[黑名单变更] {管理操作人}：已将{用户或群}移出黑名单。

[白名单变更] {管理操作人}：已将{用户或群}加入白名单。
原因：{原因}
[白名单变更] {管理操作人}：已将{用户或群}移出白名单。

[骰娘名单变更] {管理操作人}：已将{用户或群}加入骰娘名单。
原因：{原因}
[骰娘名单变更] {管理操作人}：已将{用户或群}移出骰娘名单。
```

没有可靠平台归属或缓存的全局名单显示帐号，不凭空关联另一平台昵称。


不广播命中词或被拦截原文。该正文随既有语言包翻译。

## 八、定时任务和订阅管理

### 任务管理 `schedule_manage`，例行

条件：面板保存／删除已成功。没有保存成功，不输出成功通知。

```text
[定时任务变更] {管理操作人}：已新增定时任务「{名称}」；{已启用或已停用}，执行时间：{规则}（服务器时区）。
[定时任务变更] {管理操作人}：已修改定时任务「{名称}」；{已启用或已停用}，执行时间：{规则}（服务器时区）。
[定时任务变更] {管理操作人}：已删除定时任务「{名称}」。
```

时间规则为 `每天 HH:MM`、`每 N 分钟` 或 `YYYY-MM-DD HH:MM`，有星期限制则附 `（星期限制：{配置值}）`。具体目标与适配器按需要补充；全群目标显示“所有符合条件的群组”。

旧 `.clock`／`.master clock` 入口保存成功后：

```text
[定时任务变更] {管理操作人}：已添加定时指令任务「{名称}」，每天服务器时间 HH:MM 执行。
指令：{指令内容}
[定时任务变更] {管理操作人}：已修改定时指令任务「{名称}」，每天服务器时间 HH:MM 执行。
指令：{指令内容}
[定时任务变更] {管理操作人}：已添加全局 Lua 定时函数「{名称}」，每天服务器时间 HH:MM 执行。
[定时任务变更] {管理操作人}：已修改全局 Lua 定时函数「{名称}」，每天服务器时间 HH:MM 执行。
[定时任务变更] {管理操作人}：已删除定时任务「{名称}」，共 {数量} 条。
```

身份验证指令内容在通知中改为 `[身份验证内容已隐藏]`。

### 任务触发 `schedule`，重要

条件：计划任务实际处理了至少一个目标，且不是退群动作；退群使用第五节，不重复套任务执行通知。

```text
[定时任务] 定时任务「{名称}」已提交执行。
任务 ID：{编号}
动作：{发送消息或执行指令或调用 Lua 定时函数}
已处理目标数：{数量}
任务内容：{内容或函数名}
说明：提交执行不代表平台已经确认送达，实际发送结果请查看消息日志。
```

没有任务内容就省略该行。没有可执行目标不发这条成功提交提示。执行错误按第十节处理；面板立即执行的直接返回不等于计划触发通知。

### 通知订阅管理 `notice_manage`，例行

面板规则保存／删除成功：

```text
[通知订阅变更] {管理操作人}：已新增通知规则「{规则名}」，包含 {数量} 个通知渠道。
[通知订阅变更] {管理操作人}：已修改通知规则「{规则名}」，包含 {数量} 个通知渠道。
[通知订阅变更] {管理操作人}：已删除通知规则「{规则名}」。
```

空名显示“未命名规则”；不输出 Webhook 密钥地址或 SMTP 密码。

指令调整订阅：

```text
[通知订阅变更] {管理操作人}：已关闭当前聊天的通知订阅。
[通知订阅变更] {管理操作人}：已将当前聊天的通知级别设置为{级别名称}。
[通知订阅变更] {管理操作人}：已调整{用户或群}的通知订阅，增加{级别名称}级通知。
[通知订阅变更] {管理操作人}：已调整{用户或群}的通知订阅，移除{级别名称}级通知。
```

名称只列实际选择，如 `例行、重要、关键、错误`，不再用“掩码 10”代替解释。保存失败时，不通知成功；当前窗口回复 `保存通知订阅失败，原配置未改变，请检查配置目录是否可写。`，有相应多语言翻译。

按修改后的订阅投递：被关闭／删除的窗口不会为了告知关闭而再发一次；其他仍订阅变更的窗口可收到，审计保留。

## 九、程序更新

### 发现版本 `update_available`，重要

条件：检查成功、版本较新且尚未通知过。

```text
[发现新版本] 检测到 Dice!Next 新版本：{版本}
当前版本：{当前版本}
更新策略：{策略}
检测来源：{来源}
运行平台：{OS} / {Arch}

本次更新内容：
{发布说明预览}
发布页：{Release地址}
```

策略取 `仅通知`、`自动下载`、`自动下载并安装`、`自动下载，定时安装（HH:MM，服务器时区）`；容器内为 `仅通知（容器内禁止程序自更新，请更新镜像后重建容器）`。

### 下载完成 `update_result`，重要

条件：自动下载、文件大小／SHA-256 校验与安装计划保存均成功。

```text
[更新进度与结果] Dice!Next 自动更新包已下载并通过 SHA-256 校验：{版本}
下载源：{来源}
平台包：{安装包名}
校验结果：文件大小与 SHA-256 均通过；尚未完成安装。
{下一步}
```

下一步三选一：`即将重启并安装更新。`／`将在服务器时区的 HH:MM 安装更新。`／`更新包已准备完成，等待手动安装。`。

### 安装成功 `update_result`，重要

条件：启动后安装器回报成功，且实际版本和构建号符合目标。

```text
[更新进度与结果] Dice!Next 更新安装成功：{目标版本}
当前运行版本：{实际版本}

本次更新内容：
{发布说明预览}
发布页：https://github.com/DiceZone/Dice-Next/releases/tag/{目标版本}
```

### 更新失败 `update_error`，错误

检查失败：

```text
[程序更新失败] Dice!Next 无法完成更新检查。
失败阶段：检查新版本
当前版本：{当前版本}
运行平台：{OS} / {Arch}
原因：{实际原因}
未下载或替换程序文件，将继续运行当前版本。
```

下载／校验／准备更新包失败（尚无目标版本时省略版本后缀）：

```text
[程序更新失败] Dice!Next 自动更新失败：{目标版本}
失败阶段：下载／校验／准备更新包
当前版本：{当前版本}
运行平台：{OS} / {Arch}
原因：{实际原因}
本次尚未替换程序文件，继续运行当前版本。
```

不能保存计划：

```text
[程序更新失败] Dice!Next 更新包已下载，但无法保存安装计划：{实际原因}
```

提交安装失败：

```text
[程序更新失败] Dice!Next 更新安装失败。
当前运行版本：{当前版本}
失败阶段：提交安装／重启
原因：{实际原因}
请查看后台更新状态与 updates 中的安装日志，确认文件替换结果后再重试。
```

安装后核对失败：

```text
[程序更新失败] Dice!Next 更新安装失败：{目标版本}
当前运行版本：{实际版本}
失败阶段：安装后结果核对
原因：{安装器原因或“启动后的版本与目标版本不一致”}
```

结果不可读：

```text
[程序更新失败] Dice!Next 无法读取更新安装结果：{实际原因}
```

缺少更新说明会如实显示 `本次发布的更新元数据未附带具体说明，请打开发布页查看（不代表没有改动）。`，不编造改动。独立更新错误不再被通用运行错误捕获器重复转发。

## 十、运行错误 `error`，错误级

来自实际 ERROR 日志；不是所有 WARN／审批待人工都当作运行异常。

### 插件加载／执行

```text
[插件错误] 插件「{插件名}」{操作}失败：{解释器错误原文}
```

必要时加插件文件、一个不重复的真实原因、触发群／用户／适配器。原文已包含文件名不重复堆路径。无明确操作类型不硬写“加载失败”；原文已有插件名和完整说明时保留原文。

例如解释器确实返回该错误时：

```text
[插件错误] 插件「合成大西瓜」加载失败：main.lua:123: unexpected symbol near '，'
```

如果解释器只有 `main.lua:123: syntax error`，就只显示这个，不自行判断“中文逗号写错”。

### 消息／事件发送失败

```text
[消息错误] {实际发送错误摘要}；{未重复的底层原因}
来源：插件「{插件名}」
{相关群／用户／适配器}
```

插件来源仅在确实由插件触发时出现。发送失败不误报为插件语法错误。普通发送日志仍可显示实际内容和 msgID，但骰主错误通知不再把失败正文嵌套回来。

### 其他模块通用模板

| 实际模块 | 文案框架 |
| --- | --- |
| 插件模块，无结构化插件来源 | `[插件错误] {实际错误摘要}` |
| 消息 | `[消息错误] {实际错误摘要}` |
| 通知 | `[通知错误] {实际错误摘要}` |
| 事件动作 | `[操作错误] {实际错误摘要}` |
| 自动更新，非独立更新事件 | `[更新错误] {实际错误摘要}` |
| 定时任务模块 | `[定时任务错误] {实际错误摘要}` |
| 配置 | `[配置错误] {实际错误摘要}` |
| 其他模块 | `[运行错误] {实际错误摘要}` |

最多补一个不重复的实际底层原因与必要文件路径，再补业务上下文。没有具体原因时为 `程序未返回具体错误。`。错误原文是变量，不能把所有第三方运行错误穷举成固定几十句。

同来源同种错误 60 秒内合并；下一次允许通知时可加 `（相同错误另出现 N 次，已合并）`。不同群／不同插件的错误不会被一并屏蔽。

### 通知投递失败：只写本地错误日志，不再外发

```text
向群通知测试群(192499947)发送通知失败，请检查适配器 OneBot:114514 是否可触达该通知窗口。
```

这是运行日志主文案，不是再发送一条给失败窗口的通知。平台原因保留在本地结构化详情；不重复失败正文，也不产生“通知失败→错误通知→再次失败”的无限嵌套。持续不可达也会抑制重复本地错误。

## 十一、测试与插件自定义通知

### 人工测试 `test`，重要

```text
[测试通知] 这是一条测试通知。
```

指定规则时只尝试该规则的渠道，全局测试按启用规则投递。测试可绕过常规事件勾选以验证渠道，但不修改规则，也不等同于平台确认送达。

### 旧 Lua／模组自定义通知

```text
[系统通知] {插件提供的通知原文}
```

级别由插件掩码决定。没有登记事件键的通知按级别订阅匹配，不假称是某类内置业务；仍做脱敏、CQ 文本化和递归保护。插件普通日志不全转成通知，实际 ERROR 才进入第十节。

## 十二、投递规则与实现边界

1. 只有平台真的提供并收到的事件才能通知。缺少回调不伪造结果；QQ 官方没有提供群解散／禁言／管理权限事件时，不用其他事件凑数。
2. 好友／群事件处理开关仍有效；通知勾选不会扩大权限或开启被关闭的事件处理。
3. 级别订阅包含新增同级事件；逐项勾选的规则不自动扩大，需手动勾选新增项。显式空事件列表仍表示不接收。
4. 通知不回推产生它的同一聊天，避免和指令回复重复。被关闭／删除的订阅不额外恢复一次来通知自己被删除。
5. 相同发送目标去重。明确指定发送帐号时不擅自换号；自动选择才可依既有策略寻找同平台可用帐号。
6. 事件写入 `data/audit/notice_*.jsonl`；没有匹配规则不代表事件未发生。没有发生／没有回调的事件不虚构审计记录。
7. Webhook 的 `op` 保持稳定键，`title` 是具体结果标题，`msg` 是上述可读全文；邮件主题 `[Dice!Next] {标题}`，正文相同。
8. 管理保存成功后，通知生成／发送失败不能把已完成的保存倒报为失败，诱使用户重复操作。退群接口提交同理。
9. SMTP／Webhook 为后台投递，当前没有可靠的终态送达回执，不能凭测试接口返回成功就断言对端收到；本轮没有新增邮件／Webhook 终态回执事件。进程直接崩溃、系统断电等也不能保证来得及发出通知。

参考原版 `Dice.cpp` 的被踢、禁言、好友／群邀请及审批结果，以及 `DiceEvent::note` 的操作人信息，保留“谁对谁做了什么、在哪里、为什么”。没有照搬自动拉黑踢人者／邀请人、被禁言后自动退群、其他骰娘连带处罚；普通成员全部变动不默认广播。
