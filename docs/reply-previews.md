# 回复文本预览

指令列表中的“预期回复示例”会按照当前文本所属的指令生成一组只读数据，再用正式模板引擎和平台序列化器渲染。它不是实际执行指令，也不是平台截图。

## 如何使用

- 编辑任意回复后，示例会自动刷新。普通骰点通过实际表达式引擎生成；检定使用与程序共用的 COC / BRP 判定规则。
- 理智检定同时生成骰点、成功等级、理智损失和剩余理智；成长检定保留成功成长、失败不变、失败增减三种情况；DND 检定和死亡豁免保持总值与计数一致。
- 选择具体的分级回复时，只生成该等级下成立的示例。即使继承标准回复，仍保留原指令的上下文，例如理智检定的 `{loss}`、`{san}`、`{final}`。
- 多轮掷骰、骰池、COC / DND 制卡和掷骰统计生成各自的数据结构；人物卡、日志、牌堆、快捷指令等管理文案使用虚拟数据，不读取真实玩家资料。
- “重新抽取预览”重新生成数值和随机文案。切换平台、展示方案或纯文本显示不会重掷；原生多条概率文案、嵌套 `{sample:...}` 和旧版文本引用仍交给正式模板引擎解析。
- 不存在的变量不会被随意替换成数字：保留原文并提示缺少示例上下文。帮助文本中用于讲解语法的大括号则仍是文字示例。

## 边界

示例使用预设的属性、成功率和损失表达式，不读取当前群的人物卡或房规。例如一般 COC 检定展示官规，理智检定展示 `.sc 1/1d6 60`；无损失模板展示成功损失为 0 的场景。页面会标明本次示例。

预览不发送消息、不记录真实掷骰统计、不写入人物卡、配置或数据库，不运行插件，也不请求云服务、下载媒体或验证平台权限。它不会消耗或重置实际掷骰使用的随机数。真实群设置、媒体上传、身份映射与平台展示仍需实际环境验收。

## 回归覆盖

后端遍历四种内置语言的全部文本，检查示例变量是否齐全，另对所有检定家族与等级验证算术关系、分支、平台切换与重新抽取。共享 COC 规则的回归包含八种房规、0～150 成功率和所有 D100 出目，共 120,800 次判定。

WebUI 测试直接调用不带账号和数据库的正式预览程序，验证原生理智、成长、死亡豁免、继承、概率文案、嵌套随机与未知变量；不通过真实适配器测试消息发送。
