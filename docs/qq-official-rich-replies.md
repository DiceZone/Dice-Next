# QQ 官方人物卡回复

QQ 官方适配器支持把 `.st` 查看／修改、`.pc show` 和 `.pc status` 的真实结果展示为状态卡。`.pc status` 只查看自己的当前人物卡，不修改属性。

## 开启

在 WebUI 中开启全局卡片消息模式，然后编辑 QQ 官方机器人连接：

- 人物卡样式：关闭、普通 Markdown、彩色公式。
- 快捷交互：关闭、点击填入指令的文本链接、官方按钮。

新连接默认关闭人物卡样式。全局传统文字模式或连接的传统文字覆盖优先。官方 Markdown／按钮需要该机器人的平台权限；彩色公式是否正常显示还取决于 QQ 客户端。

配置文件使用 `qq_rich_replies`（`off` / `markdown` / `math`）和 `qq_interactions`（`off` / `links` / `buttons`），适配器 API 使用对应的 `qqRichReplies` / `qqInteractions`。

## `.sn` 回复顶部状态行

群内 `.sn` / `/sn` 启用玩家自己的状态行，`.sn off` 关闭。骰主可在
**基础设置 → 回复与显示 → QQ 官方 SN 状态行**选择红色小字（默认）、引用、
普通文字、自定义格式或关闭；支持全局、类型、账号覆盖，修改后立即生效。
这与人物卡富回复样式独立，但同样遵守传统文字及会话纯文本设置。

配置保存在 `dice/qq_sn_banner`（`small_red` / `quote` / `plain` / `custom` / `off`）
和 `dice/qq_sn_template`（默认 `> {sn}`）。自定义格式最多 2048 UTF-8 字节，
必须有 `{sn}` 或 `{sn_tex}`。前者插入转义后的 Markdown 文字；后者用于
`\text{…}` 内，转义 TeX 特殊字符，单次替换不会再展开昵称中的占位符。
默认红色小字发送 `$\scriptsize\textcolor{#E5484D}{\text{…}}$`，不发送 HTML 字体标签。

公式或自定义格式被平台明确拒绝时，先降级为普通 Markdown 状态文字，再按原逻辑
尝试纯文本。超时与 5xx 不重发。关闭顶部显示保留玩家模板，并在 `.sn` 回执中
说明当前未展示。预览使用示例人物卡；本次仅验证序列化及浏览器预览，实际 QQ
客户端呈现仍需实机确认（接口成功不能证明客户端支持所有公式宏）。

## 当前会话使用普通文字

- `.bot text`：以普通文字显示当前会话状态和用法，不修改设置。
- `.bot text plain`：当前群／频道或私聊强制普通文字；Markdown 模板使用现有降级结果，关闭卡片、公式与按钮。
- `.bot text rich`：清除本会话的普通文字覆盖，恢复跟随骰主的全局与账号设置，不能绕过关闭的主开关。

设置持久保存，按机器人连接、会话目标和群聊／私聊类型隔离。可追加机器人账号尾号，例如 `.bot text plain 9000`；`.` 和 `。` 都支持。裸命令及错误参数只显示用法。普通 `.bot off` 期间仍可调整展示形式，不会重新启动机器人；WebUI 的彻底禁用仍优先。

私聊用户可设置自己的会话；群聊沿用管理权限。QQ 官方当前缺少可信的群管理员角色，官方群中允许骰主、该机器人在本群的已记录邀请人或机器人自身操作。邀请人按入群事件记录的原生 OpenID 校验，权限限于对应机器人和群；没有邀请人记录时仍由骰主设置。其他普通成员可查看用法。

正常回复在处理时保存会话偏好，异步润色与分段发送使用同一偏好。QQ、KOOK、Discord 的直接发送入口也检查目标会话设置。此开关控制文本的展示方式，原有图片、语音等独立媒体仍按原功能发送；未标记为 Markdown 的插件文字仍按字面内容处理。

## 展示内容

- HP、SAN、MP 使用当前人物卡的真实值，最大值沿用人物卡上限及现有规则。未设置的属性不补示例值，没有有效上限则不画进度条。
- 彩色条按真实比例绘制；负值、超过上限时只限制条的长度，旁边仍显示实际数值。
- 属性修改显示修改前后及差值，恢复为绿色、减少为红色。用户提供的角色名、属性名留在转义后的普通文字中；公式只包含固定宏、颜色及程序生成的数字。
- 数值变化已经完整呈现时，省略重复的默认“人物卡已更新”回执。自定义回执、公式属性说明、自动卡面重算和 DB 变化说明仍保留。
- 两列快捷操作分别为查看状态、查看人物卡、修改属性、发起检定，沿用当前指令前缀和 COC／DND 模式。所有操作只填入输入框。官方按钮还限制为触发消息的原生 OpenID，缺少该身份时不生成按钮。

## 适配器隔离与降级

指令处理器仍返回原始文字，QQ 专用展示数据附在单次回复的不可变快照上。日志、转发、其他适配器继续处理原回复；AI／插件改写内容以及显式自定义 Markdown 不套用该快照。QQ 公式渲染实现在 QQ 官方发送端，通用适配器接口仅持有不透明的可选数据。

接口明确以 HTTP 400、403 或 422 拒绝富文本时，先去掉公式／交互，再尝试原始传统文字。网络超时及 5xx 不自动重发，以免重复回复。超过卡片长度预算时直接保留原始文字。接口接受但客户端不支持某个宏时，服务端不能自动识别；可手动切到普通 Markdown。
